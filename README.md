# AttendPro BLE MVP

Приложение студента на `$mol`: PWA для компьютера/телефона и нативная Android-оболочка Capacitor. Хаб преподавателя на Node.js принимает подписанные отметки по BLE, сохраняет их на диск и возвращает проверяемые квитанции.

## Быстрый запуск на этом Mac

```sh
npm start
```

Консоль: <http://127.0.0.1:8877/>. Ключ консоли лежит в `hub/data/admin-token` — скопируйте его в поле консоли. Приложение студента: <http://127.0.0.1:8877/student/index.html>.

Собранный установочный файл: `dist/AttendPro-debug.apk`. Это debug APK для демонстрации, Android 7.0+. Для установки через USB:

```sh
adb install -r dist/AttendPro-debug.apk
```

Без USB можно перенести APK на телефон и открыть файл. Android запросит разрешение установки из выбранного источника.

## Демонстрация настоящей BLE-отметки

1. Запустите хаб с доступом из локальной сети:
   ```sh
   HOST=0.0.0.0 ALLOWED_ORIGINS=https://localhost npm start
   ```
2. В консоли введите ключ, убедитесь в статусе **BLE: advertising**, задайте название и нажмите «Начать пару».
3. Введите имя студента, создайте приглашение. Телефон и хаб должны быть в одной сети только для первоначальной настройки.
4. Установите APK. В приложении укажите `http://<IP-компьютера>:8877` и код приглашения. Разрешите Bluetooth/поиск ближайших устройств; на старых Android также геолокацию и включите системную службу геолокации.
5. После настройки интернет и Wi-Fi телефона можно отключить. Bluetooth должен остаться включённым. Нажмите «Отметиться» рядом с хабом.
6. После проверки подписи квитанции телефон показывает «Принято преподавателем», а имя появляется в консоли. Повтор не создаёт вторую отметку.
7. Завершите пару и скачайте доказательства из консоли. Экспорт содержит якоря, отметки, квитанции, сертификаты и финальный подписанный batch.

Один встроенный адаптер Mac нельзя использовать как надёжную замену паре независимых BLE-устройств. Для проверки нужен отдельный телефон/компьютер. Хаб MVP обслуживает студентов по очереди; не предназначен для массового одновременного подключения аудитории.

## Демо без радио

```sh
npm run start:demo
```

Откройте приложение студента, нажмите «Демо-режим: настроить без хаба», затем «Отметиться». Это тот же протокол подписей и квитанций с локальным хабом внутри страницы. Демо явно подписано в интерфейсе. Для переключения на реальный хаб нажмите «Сбросить данные устройства» — это удаляет локальную личность и историю.

## Чистая установка и сборка

Нужен Node.js 24+, npm. Для нативного BLE-модуля на macOS нужны Xcode Command Line Tools и разрешение Bluetooth для запускающего приложения; на Linux — зависимости и настройка адаптера из [документации bleno](https://github.com/abandonware/bleno#prerequisites).

```sh
npm ci
npm ci --prefix shell
npm ci --prefix hub
npm run build
npm test
```

`npm run build` собирает `$mol`, запускает его тесты и аудит TypeScript, готовит `dist/student` и `shell/www`. MAM скачивает модули при первой сборке; автоматический `git pull` отключён. Исходники приложения находятся в `attendpro/`; `mol/` и `node/` — управляемые MAM зависимости.

Android: JDK 21, Android SDK Platform 36, Build Tools 35/36. Создайте `shell/android/local.properties` с `sdk.dir=/путь/к/Android/sdk` либо задайте `ANDROID_HOME`.

```sh
npm run build
npm run android:sync
JAVA_HOME=/путь/к/jdk21 npm run android:apk
```

APK появляется в `shell/android/app/build/outputs/apk/debug/app-debug.apk`. Команда `npm run android:apk` также копирует его в `dist/AttendPro-debug.apk`.

## PWA и платформы

Статические файлы из `dist/student/` можно обслуживать по HTTPS. На localhost HTTPS не требуется. Манифест и service worker обеспечивают установку и повторное открытие офлайн после первого посещения.

Web Bluetooth работает в поддерживающем его браузере, например Chrome на Android/компьютере; выбор устройства требует нажатия кнопки. Safari/iPhone PWA не предоставляет этот BLE-транспорт. iOS-проект и IPA в этот MVP не входят; Android-оболочка использует [Capacitor BLE](https://github.com/capacitor-community/bluetooth-le).

Для HTTPS-хаба задайте `TLS_CERT` и `TLS_KEY`. Для PWA с отдельного origin добавьте точный origin в `ALLOWED_ORIGINS` (через запятую). HTTPS-страница не сможет выполнить онбординг через обычный HTTP из-за mixed content. Debug APK использует нативный HTTP Capacitor и допускает HTTP-онбординг в доверенной локальной сети; ключ устройства при этом не передаётся, но имя/код/публичные сертификаты передаются открыто.

## Данные и протокол

- ES256/P-256, доменное разделение подписей, SHA-256 канонических фактов.
- BLE service `c17a0001-38d4-4c6e-9f2a-5b3c7d8e9f01`: challenge `…0002`, mark `…0003`, receipt `…0004`.
- Каждая характеристика передаёт фреймы `[seq u8, total u8, payload]`. Payload 18 байт, фрейм ≤20 байт для ATT MTU 23. Challenge читается последовательными read до полного сообщения; mark пишется с подтверждением; receipt приходит notifications. Лимит сообщения 4590 байт. Начальный фрейм сбрасывает неполную сборку.
- Студент сохраняет отметку **до** отправки. Зелёный статус появляется только после проверки подписи, типа и привязки квитанции к отметке/якорю.
- Хаб последовательно обрабатывает приём/ротацию/закрытие, записывает состояние до выдачи квитанции. Повтор той же принятой отметки возвращает прежнюю квитанцию, в том числе после перезапуска и ротации открытой пары.
- Эпоха меняется каждые 5 минут. Закрытая пара не принимает отметки. Если неподтверждённая отметка вообще не дошла до хаба до смены эпохи, её старый якорь отклоняется: потребуется разбор преподавателем, а не ложный успешный статус.
- `hub/data/state.json` хранит ключи, приглашения и текущую пару. При запуске следующей пары предыдущая архивируется в `hub/data/<session_id>.json`. Не удаляйте каталог между запусками: студенты доверяют ключу этого хаба.
- Секреты хаба хранятся с правами `0600`, каталог исключён из git. На телефоне ключ/история находятся в локальном хранилище WebView; системный keystore ещё не подключён, Android backup отключён.

Это демонстрационный срез концепции v4: хаб временно выполняет роль университета и выдаёт сертификаты по приглашениям. Настоящий SSO, Giper Baza, официальный синхронизатор с Decision и ведомость университета не подключены. Квитанция подтверждает приём хабом, а не запись в официальной ведомости.

## Проверки

`npm test` запускает весь `$mol`-набор и интеграционные Node-тесты HTTP/GATT/хранения. В `TESTING.md` записаны результаты конкретного прогона и границы аппаратной проверки.
