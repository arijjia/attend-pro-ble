Вот последовательная инструкция. Всё построено на том, что уже собрано: хаб на Mac (bleno), APK в `dist/AttendPro-debug.apk`, тесты зелёные.

## 0. Подготовка (один раз)

```sh
cd /Users/masha/src/github.com/arijjia/cit/attend-pro-ble
npm ci && npm ci --prefix hub && npm ci --prefix shell
npm run build
npm test        # должно быть 7/7 pass — базовая санити-проверка перед железом
```

APK уже собран: `dist/AttendPro-debug.apk` (если меняли код студента — пересоберите: `npm run build && npm run android:sync && JAVA_HOME=$(/usr/libexec/java_home) npm run android:apk`).

Узнайте LAN-IP Mac (для онбординга телефона):
```sh
ipconfig getifaddr en0
```
Допустим, это `192.168.1.10`. Телефон и Mac должны быть в **одной Wi-Fi сети** — но только для первоначальной настройки, дальше интернет телефону не нужен.

## 1. Запуск хаба на Mac

```sh
HOST=0.0.0.0 ALLOWED_ORIGINS=https://localhost npm start
```
(`--no-ble` НЕ указываем — нужен настоящий радиохаб.)

При первом запуске macOS спросит разрешение Bluetooth для терминала — разрешите. В консоли хаба будет строчка с адресом; ключ консоли лежит в `hub/data/admin-token`:
```sh
cat hub/data/admin-token
```

## 2. Консоль преподавателя (на Mac)

1. Откройте `http://127.0.0.1:8877/`.
2. Вставьте ключ из `admin-token` → «Подключиться». Статус должен показать **`BLE: advertising`** — это значит, хаб реально вещает по Bluetooth. Если видите ошибку вместо advertising — см. «Проблемы» ниже.
3. Введите название пары (например «Тест BLE») → **«Начать пару»**.
4. Введите имя студента → **«Создать приглашение»** → запишите код (6 символов, например `AB3K9F`) и адрес `http://192.168.1.10:8877`.

## 3. Телефон (Android): установка и онбординг

1. Положите `dist/AttendPro-debug.apk` на телефон (AirDrop не сработает на Android — через USB: `adb install -r dist/AttendPro-debug.apk`, либо любым мессенджером/облаком и откройте файл; Android спросит разрешение «устанавливать из этого источника»).
2. Откройте AttendPro. В экране онбординга введите:
   - адрес хаба: `http://192.168.1.10:8877`
   - код приглашения из шага 2.
3. **«Получить ключ устройства»** — телефон сгенерирует пару ключей и получит подписанный сертификат. Появится шапка `Имя · cit`, `Радио: Capacitor BLE`.
4. Разрешите все запросы: Bluetooth, «Ближайшие устройства»; на Android ≤11 также геолокацию и включённую системную службу геолокации (без неё скан не работает).
5. Теперь Wi-Fi на телефоне можно **выключить** — дальше нужен только Bluetooth. Убедитесь, что Bluetooth включён.

## 4. Первая настоящая BLE-отметка

1. Телефон в паре метров от Mac.
2. Нажмите **«Отметиться»**. Ожидаемая цепочка статусов: `Слушаю эфир… → Подключаюсь к хабу… → Проверяю подпись якоря… → Подписываю отметку… → Отправлено, жду квитанцию… → ✓ Принято преподавателем (квитанция №1)`.
3. На Mac в консоли имя студента появляется в «Принятых отметках».

## 5. Проверки честности (то, ради чего весь протокол)

| Что делаем | Что должно произойти |
|---|---|
| Нажать «Отметиться» второй раз на той же паре | «Вы уже отмечены на …» — **без** второй отметки в консоли |
| Сорвать приложение в момент `жду квитанцию` (свайпнуть из памяти), снова отметить | Отметка сохранена локально, при повторе хаб вернёт **ту же** квитанцию №1, дубля нет |
| В консоли «Новое окно отметок» (ротация эпохи), затем отметить с телефона | Хабо́вая сторона: прежний якорь отклонён как `STALE_ANCHOR` — зелёного статуса не будет (требуется разбор), ложного успеха нет |
| Выключить Bluetooth на телефоне, отметить | Честный `Радио недоступно` / `Пара не найдена`, а не зелёный статус |
| Перезапустить хаб (Ctrl-C, `npm start`) в открытой паре, повторить доставку той же отметки | Хаб вернёт прежнюю квитанцию (состояние пережило рестарт) |

## 6. Завершение пары и доказательства

1. В консоли **«Завершить пару»** — финальный якорь + batch с merkle-корнем.
2. **«Скачать доказательства»** → `attendpro-evidence.json`: якоря, отметки, квитанции, сертификаты, подписанный batch. Откройте и убедитесь, что `private` там нет (тест это тоже проверяет).
3. С телефона историю можно показать прямо в приложении: «История отметок» — запись с `✓ Принято преподавателем`.

## 7. Вариант «компьютер вместо телефона» (Web Bluetooth)

Если второго Android нет — телефона можно заменить вторым компьютером с Chrome/Edge:

1. Попросите хаб слушать сеть (шаг 1) и откройте на втором компьютере `http://192.168.1.10:8877/student/index.html` — **именно по IP, не по localhost**.
2. Онбординг тот же (шаг 3): адрес + код. Транспорт будет `Web Bluetooth`.
3. «Отметиться»: Chrome откроет системный **пикер устройств** — выберите `AttendPro`. Дальше всё как в шаге 4.

## 8. Совсем без радио (самопроверка UI за 30 секунд)

`npm run start:demo` → открыть `http://127.0.0.1:8877/student/index.html` → «Демо-режим: настроить без хаба» → «Отметиться». Тот же протокол подписей, хаб внутри страницы; в интерфейсе явно помечено «демо». Полезно, чтобы отделить проблемы протокола/UI от проблем радио.

## Проблемы и что смотреть

- **`BLE: <текст ошибки>` вместо advertising** — обычно macOS не дала Bluetooth терминалу: Системные настройки → Конфиденциальность → Bluetooth → добавить терминал, перезапустить хаб.
- **Телефон не находит пару** — проверьте: Bluetooth включён, геолокация включена (Android ≤11), разрешения выданы, вы рядом с Mac, хаб в статусе advertising.
- **Онбординг не проходит** — телефон и Mac в одной сети, порт 8877 не закрыт файрволом macOS, адрес точно `http://<LAN-IP>:8877`.
- **Снова тестируете на том же устройстве** — «Сбросить данные устройства» в приложении (сотрёт личность и историю), и создайте новое приглашение — старый код уже использован.
- **Состояние хаба** лежит в `hub/data/` — не удаляйте каталог между запусками, иначе доверенный ключ хаба изменится и старые квитанции не сойдутся.

Хорошая последовательность первого прогона: **шаг 8 (демо) → шаг 7 (второй компьютер) → шаги 3–5 (настоящий телефон по BLE)** — так каждая следующая проверка добавляет ровно одну новую переменную.
